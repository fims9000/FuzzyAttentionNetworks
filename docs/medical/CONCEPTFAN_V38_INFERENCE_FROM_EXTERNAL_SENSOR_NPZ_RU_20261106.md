# ConceptFAN V38 — инференс сохранённой модели по своим измерениям

**Статус:** инженерный интерфейс для **синтетически обученного исследовательского прототипа**, не система медицинской диагностики и не подтверждённый метод физической идентификации причин. Оценка события — число модели, не клинически откалиброванная вероятность.

**Где код:** \`src/conceptfan_discovery/inference_v38.py\`, CLI \`scripts/infer_exogenous_source_v38.py\`, проверка \`scripts/verify_npz_inference_v38.py\`.

## 1. Что сохраняется после TRAIN/VALID

Пакет V38_EVIDENCE содержит отдельные артефакты:

- \`CHECKPOINTS/native_K2_device<device>_seed<nn>.pt\` — оригинальный **обученный Temporal ConceptFAN** (без изменения старых двух концептов), загружается только \`torch.load(weights_only=True)\` из доверенного локального хранилища; SHA сравнивается с манифестом.
- \`SOURCE_STATES/device<device>_V38_source.json\` — **измеренное**, а не симуляторное определение источника: оценённые TRAIN-проекции пар AB/AC/BC, TRAIN-порог согласования, порог отрицательного контроля прибора и квитанция независимого контрольного воздействия. Никаких истинных \`H\` или \`S\`, скрытых меток генератора, TRAIN/TEST пользовательских записей.
- \`INFERENCE_BUNDLES.json\` — **ровно 60** отдельных комбинаций: устройство × обученная инициализация × тип исхода. Для каждой сохранены исходная голова K2, добавочный коэффициент \(\gamma\) из TRAIN и *результат* двух независимых VALID-допусков. При запуске на новых входных данных эти параметры **не изменяются**.
- \`FROZEN_TEST_PREDICTIONS.npz\` и \`REOPEN_INFERENCE_AUDIT.json\` — научная проверка воспроизводимости и сравнения. Нужны для QA, **не используются во время пользовательского инференса**.

Идентификаторы \`device-seed\`, \`nn-seed\` и \`outcome-case\` — идентификаторы синтетической модели, а не реального пациента или аппаратуры. В частности, \`healthy\` означает вид обучающего экспериментального закона исхода, **не вывод «здоров/болен»**.

## 2. Вход: измерения и маски

Подготовить \`.npz\` с двумя массивами, и **только** ими:

- \`x\`: \`numpy.float32\` или \`float64\`, размер \`(N,16,12)\`, реальные наблюдавшиеся значения каналов, выровненные по времени;
- \`observed\`: \`numpy.bool_\`, точно той же формы. \`True\` означает, что данное число действительно наблюдалось. Если \`False\`, соответствующая ячейка может содержать \`NaN\`, она не используется моделью. При \`True\` NaN/Inf запрещены.

Минимум N=1, максимум N=10000 в одной операции. Исходные каналы K2 — 0–3; три измерительные системы A=(4,5), B=(6,7), C=(8,9); контрольный прибор — канал 10. Канал 11 не является дополнительным целевым концептом.

**Нельзя переносить эту нумерацию на реальные устройства автоматически:** без документированной схемы каналов, калиброванного исполнительного механизма и физически подключённого контроля приборных помех успешное исполнение кода не означает корректности измерительной интерпретации.

Пример подготовки собственного входа (значения \`sensor_tensor\` и \`observed_mask\` берутся из *своего* источника данных; этот пример не создаёт их):

\`\`\`python
from pathlib import Path
import numpy as np

assert sensor_tensor.shape == observed_mask.shape
assert sensor_tensor.ndim == 3 and sensor_tensor.shape[1:] == (16, 12)
assert observed_mask.dtype == np.bool_
np.savez_compressed(
    Path("observations.npz"),
    x=sensor_tensor.astype(np.float32),
    observed=observed_mask,
)
\`\`\`

## 3. Запуск без генератора и без тестовых меток

\`\`\`bash
PYTHONPATH=src:. python scripts/infer_exogenous_source_v38.py \
  --model-dir V38_EVIDENCE \
  --device-seed 20261231 \
  --nn-seed 11 \
  --outcome-case healthy \
  --input-npz observations.npz \
  --output-json research_predictions.json
\`\`\`

Процесс загружает один ранее обученный Transformer, TRAIN-голову исходных концептов, сохранённую TRAIN-проекцию источника, внешнюю калибровочную квитанцию и результат VALID. Затем вычисляет новый прогноз **только по предоставленному \`x\` и \`observed\`**. Никакие латентные истинные \`S\`, настоящие матрицы смешивания, ярлыки исхода, TEST-протокол или генератор для этого не нужны.

Новые наблюдения не используются для дообучения, перекалибровки, выбора нового концепта или изменения научных порогов. Выходной файл не перезаписывается автоматически; все данные в нём остаются локальными у оператора. Доверенные снимки модели должны храниться в защищённом каталоге. \`weights_only=True\` — не криптографическая гарантия подлинности.

## 4. Выход и объяснения

Выход \`research_predictions.json\` включает для каждого эпизода:

- \`model_event_probability\` и \`model_event_probability_without_extra_source\`;
- разницу **в процентных пунктах**, а не число произвольной нечёткой принадлежности;
- \`decision_code\`: \`SOURCE_ACCEPTED\`, \`MONITOR_UNOBSERVED\`, \`MONITOR_DETECTED_ANOMALY\`, \`INSUFFICIENT_PAIRED_MEASUREMENTS\`, \`SOURCE_VIEWS_DISAGREE\`, \`FAILED_TWO_INDEPENDENT_VALIDATIONS\`, \`EXTERNAL_CALIBRATION_REFUSED\`;
- число реально **совместно наблюдавшихся** временных точек для каждой пары AB/AC/BC и для контроля прибора;
- оценённый параметр концепта **только в техническом поле и только при допуске**;
- предупреждение: физический смысл неизвестен; общий сигнал, обходящий внешний контроль, может быть неотличим от настоящего источника; пропущенные значения не выдавались за измерения.

В случае отсутствующего мониторинга или каналов, несогласия источников, отсутствующей внешней калибровки или отрицательного VALID **логит и прогноз K2 воспроизводятся без добавочного вклада**.

## 5. QA / граница воспроизводимости

\`\`\`bash
PYTHONPATH=src:. python -m pytest -q \
  tests/discovery/test_source_persistence_v38.py \
  tests/discovery/test_inference_v38.py

PYTHONPATH=src:. python scripts/verify_npz_inference_v38.py \
  --evidence-dir V38_EVIDENCE \
  --out-dir V38_EVIDENCE/EXTERNAL_NPZ_INFERENCE_QA
\`\`\`

Вторая команда — QA и **только она** использует известный синтетический генератор для подготовки контрольных внешних \`.npz\`; сама общая библиотека инференса его не импортирует. Скрипт проверяет 30 запусков по 2 × 3 × 5 сочетаниям устройства, сети и неисправности на совпадение с сохранёнными индивидуальными TEST-предсказаниями. Для ввода подаются \`NaN\` во всех скрытых ячейках, чтобы доказать, что недоступные значения не используются.

Математическая граница V38 подтверждена конструктивным примером \`observational_equivalence_v38.py\`: если приборная помеха по всем измерительным системам точно повторяет направление физического источника, а контрольный канал её не видит, два мира с разной физической энергией источника **имеют полностью одинаковые измерения**. Доступная модель обязана одинаково на них отвечать. Интервенции в прошлом не устраняют этого недостатка данных в текущем наблюдении.

**Критерий использования в новой физической задаче:** прежде чем доверять концепту, необходимо независимо подтвердить соответствие каналов/временных единиц, независимость ошибок измерений, назначение внешнего исполнительного механизма, реальное подключение контрольного датчика и валидность обученной головы на новом распределении. Пока этих проверок нет — только демонстрационный режим.
